## 1. Basic CISC x86 Assembly and Instruction Execution Cycle

### Exercise 1

a) How many logical cores: 4 CPU sockets, 4 cores per socket, and 2 threads per core?

- Total logical cores = Number of sockets × Cores per socket × Threads per core
- Total logical cores = 4 × 4 × 2 = 32 logical cores

b) How many physical cores: 2 CPU sockets, 4 cores per socket, and 2 threads per core?

- Total physical cores = Number of sockets × Cores per socket
- Total physical cores = 2 × 4 = 8 physical cores

c) Which feature of the CPU has direct impact on the maximum addressable space?

- The bit width of the address bus (or address space) directly impacts the maximum addressable space
- For example, a 32-bit CPU can address 2^32 = 4GB of memory, while a 64-bit CPU can address 2^64 bytes

d) Can a uni-processor computer run multiple programs in fake concurrency? Explain.

- Yes, a uni-processor computer can run multiple programs in fake concurrency through time-sharing
- The operating system rapidly switches between different processes, giving each one a small time slice
- This creates the illusion of concurrency (called pseudo-concurrency or fake concurrency), even though only one process is actually executing at any given moment
- This is achieved through context switching, where the state of one process is saved and another is loaded

### Exercise 4

What will happen when the ALU executes the instruction at address 0x330F?

The instruction at 0x330F is "Div Ax" which attempts to divide a value by the contents of Ax register.

Let's trace the program execution:

- 0x330B: Mov Ax, 0x000A (Ax = 10 in hexadecimal)
- 0x330C: Add Ax, 0x0002 (Ax = 10 + 2 = 12)
- 0x330D: Mul Ax, 0x000A (Ax = 12 × 10 = 120)
- 0x330E: Xor Ax, Ax (Ax = 0, since XOR of any value with itself is 0)
- 0x330F: Div Ax (This attempts to divide by zero, since Ax = 0)

Therefore, when the ALU executes the instruction at 0x330F, a division by zero exception/interrupt will occur because trying to divide by zero is an illegal operation. This will typically trigger the CPU's exception handling mechanism, likely causing the program to terminate abnormally.

### Exercise 5

a) Assuming the address of the first instruction is 0xFBC0 and an interrupt occurs after the 4th instruction, what will be the value of the PC register pushed onto the stack?

First, let's calculate the address of each instruction:

- 1st instruction (Mov Ax, [0X3F55]): 0xFBC0 to 0xFBC3 (2 words = 4 bytes)
- 2nd instruction (Mov Bx, [0X3F56]): 0xFBC4 to 0xFBC7 (2 words = 4 bytes)
- 3rd instruction (Mul Cx, 0x0000): 0xFBC8 to 0xFBC9 (1 word = 2 bytes)
- 4th instruction (Xor Bx, Cx): 0xFBCA to 0xFBCB (1 word = 2 bytes)
- 5th instruction (Inc Ax): 0xFBCC to 0xFBCD (1 word = 2 bytes)

Since the interrupt occurs after completing the 4th instruction, the PC would be pointing to the 5th instruction. Therefore, the PC value pushed onto the stack would be 0xFBCC.

b) Which component of the computer system is responsible for pushing the PC value onto the stack? Why?

The Interrupt Controller in conjunction with the CPU is responsible for pushing the PC value onto the stack when an interrupt occurs. This is done because:

- When an interrupt occurs, the current execution must be suspended
- The system needs to remember where to return after handling the interrupt
- Saving the PC on the stack allows the program to resume execution from where it left off
- It's part of the process of saving the execution context (program state)

c) Which stack are we referring to?

We are referring to the system stack, which is a region of memory managed by the CPU through the stack pointer register (SP). In x86 architecture, this is typically managed using the SS (Stack Segment) and SP/ESP (Stack Pointer) registers. This stack is used for:

- Storing return addresses during procedure calls
- Saving register values during interrupts
- Passing parameters to functions
- Allocating local variables in functions

## 2. Process Management

### Exercise 1

a) What is a process? and what's the relationship with a program?

- A process is an instance of a program in execution. It's an active entity that requires resources like CPU time, memory, files, and I/O devices to accomplish its task.
- A program is a passive entity, which is a file containing a set of instructions stored on disk.
- Relationship: A program becomes a process when its instructions are loaded into memory and executed by the CPU. Multiple processes can be created from the same program.

b) What is a PID, and how can you use it to terminate the execution of a program?

- PID (Process Identifier) is a unique numerical identifier assigned to each process by the operating system.
- To terminate a program using its PID:
  - In Unix/Linux systems: `kill PID` or `kill -9 PID` (forceful termination)
  - In Windows: Using Task Manager or `taskkill /PID PID_number /F` in command prompt

c) The operating system uses a data structure to represent each process in the system. What is that structure called? Give five information fields that are kept in that data structure.

- The data structure is called the Process Control Block (PCB) or Task Control Block (TCB).
- Five fields typically stored in a PCB:

  1. Process ID (PID)
  2. Process State (running, waiting, ready, etc.)
  3. Program Counter (address of the next instruction)
  4. CPU registers information (for context switching)
  5. Memory management information (base and limit registers, page tables)

  Additional fields include:

  - CPU scheduling information (priority, scheduling queues)
  - I/O status information (list of open files)
  - Accounting information (CPU time used, time limits)
  - Parent process ID (PPID)

d) What is a system call? Give three examples and explain their function.

- A system call is an interface between a user-level program and the operating system kernel, allowing processes to request services from the operating system.

Three examples:

1. `fork()`: Creates a new process by duplicating the calling process
2. `exec()`: Replaces the current process image with a new process image
3. `open()`: Opens a file or device, returning a file descriptor

Other examples include:

- `read()/write()`: Read from or write to a file descriptor
- `exit()`: Terminates the calling process
- `wait()`: Waits for a child process to terminate

e) Explain what the fork() system call performs in a C-program running on a Unix-like system. Describe what happens when a process executes that function.

- The `fork()` system call creates a new process by duplicating the calling process. The new process is called the child process, and the original process is called the parent process.

When a process executes fork():

1. A new process is created with a new PID
2. The child process is an exact copy of the parent process (including memory, open files, etc.)
3. Both processes continue execution from the instruction following the fork() call
4. fork() returns different values in the parent and child:
   - In the parent process: Returns the PID of the child process
   - In the child process: Returns 0
   - Returns -1 if fork fails

f) Give three reasons that may lead a program to be suspended.

1. I/O operations: Process is waiting for input/output operations to complete
2. Resource allocation: Process is waiting for resources (memory, files, etc.) that are currently unavailable
3. Explicit synchronization: Process has executed a wait operation (e.g., on a semaphore or for a child process)

Other reasons:

- Timer interrupt (time quantum expired in round-robin scheduling)
- Higher priority process becomes ready
- User-initiated suspension (Ctrl+Z in Unix)
- Deadlock prevention

g) What is a Zombie state in Unix-like systems? How can you simulate that?

- A Zombie process (or defunct process) is a process that has completed execution but still has an entry in the process table because its parent hasn't called wait() to read its exit status.

To simulate a zombie process:

```c
#include <stdlib.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        // Child process
        exit(0); // Child terminates immediately
    } else {
        // Parent process
        sleep(60); // Parent sleeps without calling wait()
    }

    return 0;
}
```

h) What is an orphan process in Unix-like operating systems?

- An orphan process is a process whose parent process has terminated, but the child process continues to run.
- In most Unix-like systems, orphaned processes are adopted by the init process (PID 1), which periodically calls wait() to clean up any terminated orphan processes.

i) What is context switching? and why is that needed?

- Context switching is the process of saving the state (context) of a running process so that it can be restored and resumed later, and loading the saved state of another process to continue its execution.

Context switching is needed for:

- Implementing multitasking (allowing multiple processes to share a single CPU)
- Handling interrupts and system calls
- Implementing time-sharing systems
- Allowing higher priority processes to execute when they become ready

j) What is an interrupt? and what is the relation with context switching?

- An interrupt is a signal to the processor indicating that an event needs immediate attention, causing the processor to suspend its current activity and execute an interrupt handler.

Relation with context switching:

- Interrupts often trigger context switches as they require the CPU to stop the current process and handle the interrupt
- After handling the interrupt, the system might decide to resume the interrupted process or switch to another process
- The interrupt handling mechanism saves the context of the currently running process before handling the interrupt, which is a key part of the context switching mechanism

k) Can we have an interrupt without context switching? If yes, given an example.

- Yes, we can have an interrupt without context switching.

Example:

- A fast interrupt handler that performs a quick operation (like updating a system clock) and then returns control to the same process that was interrupted
- Some real-time operating systems use interrupt handlers that complete their work and return to the interrupted task without performing a context switch
- Hardware-managed interrupts that don't require OS intervention (e.g., memory refresh interrupts)

l) What is the difference between software-based interrupts and hardware-based interrupts? Give three examples for each type of interrupt.

Software-based interrupts:

- Generated by executing specific instructions in the program
- Typically used for system calls or to signal exceptional conditions
- Synchronous (occur at specific points in program execution)

Examples:

1. System calls (int 0x80 in Linux, syscall in x86_64)
2. Exception conditions (division by zero, page fault, illegal instruction)
3. Breakpoints in debugging

Hardware-based interrupts:

- Generated by hardware devices external to the CPU
- Asynchronous (can occur at any time, independent of program execution)
- Typically signal I/O completion or hardware events

Examples:

1. Timer interrupts (periodic interrupts for time-keeping)
2. Keyboard/mouse input interrupts
3. Disk I/O completion interrupts
4. Network packet arrival interrupts
5. Power management interrupts (low battery, overheating)
